# emoji 翻译器 — 设计文档

日期：2026-09-11
状态：设计已获用户批准，待实现
模块 id：`emoji`　中文名：emoji 翻译器（id 与路由前缀统一为 `Emoji`）

## 背景

FlowKit（流光）新增「emoji 翻译器」模块：输入任意中文文本（一段话、一首诗、成语），**逐字转化为谐音/意象 emoji**，输出可直接复制分享，供他人猜谜。

用户提供的 14 个参考示例（作为黄金验收用例，全部收录为短语库种子）：

| emoji | 原文 |
|---|---|
| 🍏🌹🐷🐴 | 青梅竹马 |
| 😄👆🌹🔥 | 喜上眉梢 |
| 🐔✈️🥚🔨 | 鸡飞蛋打 |
| 🎈👄👈🐍 | 七嘴八舌 |
| ✅🐂🤘🏼🎹 | 对牛弹琴（✅ 取对勾意象 =「对」） |
| ♨️♨️🌞👆 | 蒸蒸日上 |
| 🧊🧊🈶🎁 | 彬彬有礼 |
| 🚶🐴👀🌸 | 走马观花 |
| 🐠🎵♻️🍚 | 余音绕梁 |
| 🎨🐍☁️🦶 | 画蛇添足 |
| 🐦🌧️🌼🤔️ | 鸟语花香 |
| 🐷☀️💎🎈 | 珠光宝气 |
| 👨👩🧓🧒 | 男女老少 |
| 🐶🐔🪂🧱 | 狗急跳墙 |

映射机制共三类：**纯谐音**（竹→🐷、梢→🔥）、**意象**（上→👆、对→✅）、**联想**（青→🍏）。全部为逐字映射。

## 需求范围

### 一期包含

- 输入中文文本 → 生成 emoji，**双版本输出**（精确版 / 纯 emoji 版）
- 单字候选切换：点按结果中某个字，循环切换其候选 emoji
- 历史记录：生成自动入库，可回看、回填重新生成、删除
- 词库两层结构：音节表 + 短语库，全部离线内置

### 明确不做（YAGNI）

- 图片分享卡片（需截图/绘制能力，二期再议）
- 自定义映射词典（与候选切换功能重叠）
- 运行时 LLM 调用（保持离线、免费、秒出）
- App 内置猜谜玩法（本模块定位为生成器）

## 核心机制

### 1. 两层词库数据模型

**音节表** `src/modules/emoji/data/syllables.json`，覆盖普通话全部约 400 个**无调音节**：

```json
"zhu": {
  "exact":   [{ "emoji": "🐷", "label": "猪" }, { "emoji": "🎋", "label": "竹" }],
  "similar": [{ "emoji": "🍚", "label": "粥（zhu↔zhou 近音）" }]
}
```

- `exact`：同音候选（**有序**，第一个为默认），每个音节 2~5 个
- `similar`：近似音候选，仅用于纯 emoji 版兜底，每个音节 0~3 个
- 极少数冷门音节（如无合适 emoji 的 `dia`）允许为**空条目**（两个数组均为空），运行时自动走降级路径
- 与声调无关：音节键一律为无调拼音（`qing` 而非 `qīng`），声调差异天然视为同音
- 近似音判定规则（生成管线执行）：平翘舌（z/zh、c/ch、s/sh）、前后鼻音（an/ang、in/ing 等）、n/l、f/h、常见元音近似（u/ou、ing/in 等）
- 候选直接内联 emoji（**不引用其他音节**），运行时零查找逻辑

**短语库** `src/modules/emoji/data/phrases.json`，成语/俗语/名句的**整词编排**：

```json
"青梅竹马": ["🍏", "🌹", "🐷", "🐴"]
```

- 种子：上文 14 个黄金示例原样收录；一期扩充至 300~500 条（常用成语/俗语）
- 收录约束：仅收纯汉字短语，emoji 数组长度必须等于文字字符数

### 2. Token 模型（运行时统一抽象）

```ts
interface Token {
  char: string;              // 原字符
  type: 'hanzi' | 'other';   // other = 标点、数字、字母、空白
  candidates: string[];      // 候选 emoji，按「精确在前、近似在后」排序
}
```

- 命中短语的字位：`candidates[0]` = 短语编排结果，其后接该字的音节表候选 → **短语命中后仍可点按换候选**，交互统一
- 未命中短语的汉字：`[exact候选…, similar候选…]`
- 生僻字 / 冷门音节：`candidates = []`（空候选，走降级）
- 非汉字字符：原样保留，不参与转换

### 3. 转化流程（`translator.ts` 纯函数）

```
输入文本
  → 规范化为字符序列（保留换行、标点）
  → 短语扫描：对连续汉字段做短语库「最长匹配」
      （实现：短语库按文本建 Map，从每个位置起按最长长度递减查表，命中即取）
  → 命中区间：整词编排生成 Token（candidates 见上）
  → 剩余汉字：pinyin-pro 分词判断多音字 → 无调音节 → 查音节表
  → 非汉字：type='other' 原样保留
  → 输出 Token[]
```

- 多音字：使用 pinyin-pro 的分词能力（如 `segment`/`multiple` 模式）取上下文首选读音；读音判断错误时可通过候选切换补救
- 重叠短语（如「心相印」与「心心相印」）：最长优先

### 4. 双版本渲染语义（基于同一份 Token[]）

| | 默认取 | 无候选时 | 点按切换 |
|---|---|---|---|
| **精确版** | 第一个精确候选（短语编排或 exact[0]） | 显示**原字** | 在全部候选中循环 |
| **纯 emoji 版** | 精确优先，其次近似（即 candidates[0]） | 显示 **❓** | 在全部候选中循环 |

- 两版本**各自独立**维护选择状态（点按只影响被点击的版本）
- 标点、数字、英文、换行在两版中**均原样保留**（保留断句与结构，帮助猜谜者理解）

## 模块架构

按项目 AGENTS.md 模块约定，参照 `trigger/`、`reaction/`：

```
src/modules/emoji/
├── index.ts                    # ModuleConfig（id: 'emoji', name: 'emoji 翻译器',
│                               #   homeRoute: 'EmojiTranslator', enabled: true）+ registerEmojiModule()
├── types/index.ts              # Token / EmojiCandidate / SyllableEntry / PhraseEntry / HistoryItem
├── data/
│   ├── syllables.json          # 音节表（生成管线产物）
│   └── phrases.json            # 短语库（生成管线产物）
├── services/
│   ├── pinyin.ts               # pinyin-pro 封装（取无调音节）
│   ├── translator.ts           # 核心转化纯函数
│   ├── translator.test.ts      # 转化测试（含黄金用例，与源码同目录，同 trigger 惯例）
│   ├── dictData.test.ts        # 词库结构校验
│   └── historyStorage.ts       # AsyncStorage 持久化
├── store/index.ts              # useEmojiStore（Zustand）
├── screens/
│   ├── EmojiTranslatorScreen.tsx   # 主页：输入 + 生成 + 结果
│   └── EmojiHistoryScreen.tsx      # 历史记录
└── components/
    └── EmojiResultView.tsx         # 单版本渲染 + 点按换候选
```

- `App.tsx`：调用 `registerEmojiModule()`，并挂 2 个 Stack.Screen：
  - `EmojiTranslator`（title：emoji 翻译器）
  - `EmojiHistory`（title：历史记录）
- 首页卡片由 `moduleRegistry` 自动渲染，无需改 HomeScreen
- 双端启用（`enabled: true`，无平台限制）

## 页面与交互

### EmojiTranslatorScreen（主页）

- 多行输入框（支持诗句换行），「生成」按钮（空输入时禁用）
- 结果区：
  - 分段控件切换「精确版 / 纯 emoji 版」
  - emoji 大字号逐字展示；点按某字循环切换候选
  - 「复制」按钮：复制当前所选版本渲染后的纯文本串
- 生成成功时自动写入历史
- 导航栏右上角入口 → 历史页

### EmojiHistoryScreen（历史页）

- 列表项：原文摘要（截断显示）+ 生成时间
- 点击条目 → 回填主页输入框并重新生成
- 删除单条（滑动或按钮）；「清空全部」带二次确认

### 历史记录策略

- AsyncStorage key：`@flowkit:emoji:history`，格式 `{ id, text, createdAt }[]`
- 上限 100 条，超出淘汰最旧
- **只存原文本与时间戳**，点击时重放转化（纯函数）：
  - 词库升级后，历史条目效果自动变好
  - 手动点按的候选微调不入库（保持简单）

## 边界处理

- 输入上限 **200 字符**，超出时提示且不生成（防长文本渲染卡顿）
- 空输入 → 生成按钮禁用
- 纯标点 / 数字 / 英文 → 原样输出，不报错
- 词库数据为打包静态资源（`import` JSON），无运行时加载失败路径，不做额外兜底

- 音节键为合法无调拼音（正则）；`exact` 非空的音节占比 ≥ 95%（允许个别冷门音节的空条目）

- 短语包含的汉字均可在音节表中找到对应音节键（值可为空条目，保证候选切换可回落）

## 词库生成管线（开发期一次性，不涉及运行时）

1. **音节表**：以普通话约 400 个无调音节为清单，AI 批量生成候选（每音节 exact 2~5 个 + similar 0~3 个）→ 自动化校验（emoji 合法性、去重、结构）→ 抽检
2. **短语库**：14 例种子原样收录 + 常用成语/俗语扩充至 300~500 条 → AI 编排 → 抽检
3. 产物为 JSON 静态资源直接入库；数据格式在 `types/` 中注释说明，便于后续手动扩充
4. 校验由 `dictData.test.ts` 兜底，扩充后跑测试即可发现结构问题

## 实现注意事项

- **新依赖 1**：`pinyin-pro`（纯 JS、离线、含分词与多音字）。实现第一步先验证 RN 打包兼容性
- **新依赖 2**：复制功能需剪贴板能力。RN 新版核心已移除 `Clipboard`，需引入 `@react-native-clipboard/clipboard`（含原生模块，需重新构建原生工程）；实现时先确认 RN 0.86 是否仍内置 Clipboard
- **音节键校准**：`ü` 系音节（lü、nü、jue 等）的音节表键写法必须与 pinyin-pro 输出一致（实现时以实际输出为准统一，如 `lv`/`lü` 二选一）
- 词库生成是 QA 重点：黄金用例是全模块的质量锚点，14 例必须逐字通过
