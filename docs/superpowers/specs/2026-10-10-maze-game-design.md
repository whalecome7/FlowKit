# 迷境（走迷宫小游戏） — 设计文档

日期：2026-10-10
状态：已获用户批准（交互原型经浏览器试玩确认）

## 背景与定位

FlowKit 新增「迷境」模块（id: `maze`）：一个靠虚拟摇杆控制小球穿行迷宫的休闲小游戏。核心诉求来自用户：

- 样式简单但糖果色，有色彩趣味
- 摇杆控制小球**流畅连续移动**（非格子步进），走过的路径实时显示
- 迷宫可刷新、可调难度；每个迷宫带随机种子，凭种子可复现一模一样（含形状）的迷宫
- 形状不局限于四边形，有不规则轮廓
- 要有趣味性和一定难度；移动端大迷宫需要镜头缩放与移动
- 有历史记录，可从历史重进某个迷宫查看（含当时的轨迹）
- 第一版目标：最经典的"起点→出口"模式，后续可能扩展其他模式

设计与算法已在浏览器原型（`.superpowers/brainstorm/79455-1791618974/content/maze-play.html`）中完整实现并经用户试玩确认；本文档为该原型的定稿规格。

## 玩法规则

- **角色**：糖果色小球，摇杆（或键盘辅助）连续控制，撞墙沿墙滑行
- **目标**：从绿色起点走到金色星星终点即通关。无失败条件
- **计时**：首次推动摇杆那一刻开始计时，实时显示 `mm:ss.d`
- **步数**：小球中心每进入相邻新格 +1（回头路也计），实时显示
- **通关判定**：球心位于终点格内且距终点格中心 < 0.6 格
- **结算**：弹出结算卡（用时 / 步数 / 该难度最佳），按钮「再来一次（同种子）」「新迷宫」；**不做**"新纪录"提示
- **提示**：💡 按钮显示距终点剩余格数（BFS 最短路）

## 种子机制

- 种子为 7 位数字；同一「种子 + 难度」→ **完全确定**的迷宫：形状类别与参数、迷宫结构、起终点、糖色谱全部由该种子派生（唯一随机源 `mulberry32(seed)`，随机消费顺序固定）
- 顶部显示当前种子，点击弹出面板：输入任意种子生成 / 随机 / 复制
- 「新迷宫」= 新随机种子并静默生成（不弹提示）；「重开」= 同种子清空进度

## 难度（4 档，尺寸 + 形状复杂度 + 拓扑三者联动）

| 键 | 显示名 | 每边格数 N | braid（死路打通比） | 形状池 |
|----|--------|-----------|--------------------|--------|
| easy | 轻松 | 13 | 0.85 | circle, ellipse, capsule |
| normal | 普通 | 19 | 0.55 | heart, flower, hexagon, ellipse |
| hard | 困难 | 27 | 0.25 | star, crescent, flower |
| hell | 地狱 | 35 | 0 | star, crescent, organic |

- braid 越大 → 死路被打通成环路的比例越高 → 路线冗余多、容错高
- 低难度偏向规整宽形状，高难度偏向窄而复杂的形状（星星/月牙的可用格少、凹角多）

## 形状库（9 种，均为多边形定义）

形状统一为"参数曲线采样成闭合多边形"（240 点以内），点入判定用射线法。多边形坐标 `(u, v)` 均归一化到 `[-1, 1]`（v 向上）：

| 键 | 名称 | 定义 |
|----|------|------|
| circle | 圆形 | 半径 0.92 |
| ellipse | 椭圆 | x=0.95cosθ, y=0.72sinθ |
| capsule | 胶囊 | 横长圆角矩形：半圆 r=0.5，圆心 (∓0.62, 0) |
| hexagon | 六边形 | r=0.9，顶点角 -60°+60°k |
| heart | 心形 | x=16sin³t, y=13cos t−5cos2t−2cos3t−cos4t；x/16，y 归一化 (y+17)/14.6−1 |
| star | 五角星 | 10 顶点交替 0.95 / 0.42 |
| flower | 花朵 | r = 0.62 + 0.33·cos(5θ) |
| crescent | 月牙 | 外圆 r=0.92（57.5°→302.5°）+ 内圆 圆心(0.30,0) r=0.80（284°→76° 经 180°，凹口朝右），两弧交于 (0.494, ±0.776) |
| organic | 有机形 | r = 0.86·(1 + 0.1sin(3θ+a1) + 0.075sin(5θ+a2) + 0.05sin(7θ+a3))，a1..a3 由种子的 rng 生成 |

## 迷宫生成算法（确定性流程）

1. `rng = mulberry32(seed)`
2. `shapeKey = pool[floor(rng() × pool.length)]` → 生成形状多边形（organic 的形状参数也消耗该 rng）
3. 形状网格 `inS`：网格尺寸 `G = 2N+1`；仅奇数坐标（格 (i,j) ↔ 网格 (2j+1, 2i+1)）做点入判定，其余为 false
4. **起点种子格**：距形状中心最近的 inS 格
5. **DFS 迭代回溯生成迷宫**：仅在 `inS` 格之间打通（邻格步长 2，中间墙单元置 0）。**这保证了"所有可达格天然连通、无不可达区域"**
6. **braid**：收集所有死路格（开放邻居数 = 1），rng 洗牌后按比例打通"当前为墙、且对面格在形状内"的随机一面（形成环路）
7. **终点**：从起点 BFS 得最远格 a，再从 a BFS 得最远格 b；(a, b) 即起终点（保证直径路径最长）
8. 换算格坐标 `[i, j] = [(c−1)/2, (r−1)/2]`（注意网格坐标是 [行 r, 列 c]，转格坐标须行列互换——原型开发中曾在此处出过错）

输出：`{ seed, diffKey, N, G, shapeKey, cells[G][G](0 通/1 墙), inS[G][G], start[i,j], end[i,j] }`

## 坐标系与物理

世界单位 = 迷宫单元（1 格 = 2 单元）：

- 格 (i,j) 世界范围 `[2i+1, 2i+2] × [2j+1, 2j+2]`，中心 `(2i+1.5, 2j+1.5)`
- 小球半径 0.34 单元（走廊宽 1 单元，两侧各余 0.16）
- 当前格判定：`i = floor((x−1)/2)`, `j = floor((y−1)/2)`
- 轨道点 = 途过的格中心连线

**移动**：

- 速度 = 11 单元/秒 × 幅度^1.15；摇杆死区 0.12（支持键盘 WASD/方向键合并输入，仅桌面辅助）
- 碰撞：小球 AABB 与墙单元 AABB；**轴分离**处理（先 x 后 y），撞墙时对移动量二分逼近（8 次迭代）钳制到接触位置 → 自然沿墙滑行
- 碰撞查询直接读 `cells` 数组（通道被打通处 cells=0），查询范围仅小球周围 3×3 单元

## 镜头系统

- 状态 `{ x, y, s }`（s = 每单元像素/dp）；`fit = min(vw, vh) / (G + 1.6)`；初始 `s = clamp(max(fit, 10), 10, 14)`；缩放范围 `[clamp(fit, 4, 10)（下限 4）, 22]`
- **自动跟随**：死区 = 视口 30%；小球在死区内镜头静止，出死区镜头平滑追踪（每帧 lerp ≈ dt×7）
- **手动操作**（canvas 手势）：
  - 单指拖动 = 平移；双指捏合 = 以两指中点为锚缩放（增量式）；滚轮 = 以鼠标为锚缩放
  - 双击 = 回到跟随模式；缩略图点击 = 镜头跳转到该位置
  - 手动操作后 `follow=false`、暂停跟随 2 秒；恢复条件：双击 / 🎯按钮 / 小球在移动且出死区
- 镜头中心 clamp 在迷宫边界内；迷宫小于视口时自动居中全览
- **RN 实现**：外层 `View`（overflow: hidden）+ 内层大 `Svg` 用容器 transform 平移（`setNativeProps` 直写）；备选 `viewBox` 方案

## 轨迹

- 数据：格序列（含起点），步数 = 序列长度 − 1
- 渲染：格中心连线，线宽 0.24 单元，圆头圆角
- 三种样式（按钮循环切换）：
  - **彩虹**（默认）：每步 `hsl((n×15)%360, 85%, 52%)`
  - **单色**：`pal.wallDark`
  - **渐隐**（实时渐隐）：`alpha = 0.78^age`（age = 距最新步数），alpha < 0.06 不绘制；该模式下每进一格全量重绘（带透明度过滤，实际只需重画最近 ~12 段）
- 幽灵轨迹（历史查看）：同画法，`rgba(120,118,140,.85)`，宽 0.2

## 糖色谱（6 套，按 `seed % 6` 选取）

| 名称 | wall（墙） | wallDark | bg（背景） |
|------|-----------|----------|-----------|
| 紫莓 | #a78bfa | #8b5cf6 | #faf7ff |
| 薄荷 | #34d399 | #10b981 | #f2fdf8 |
| 蜜桃 | #fb923c | #f97316 | #fff7ed |
| 蓝莓 | #60a5fa | #3b82f6 | #f3f8ff |
| 莓果 | #f472b6 | #ec4899 | #fdf2f8 |
| 抹茶 | #84cc16 | #65a30d | #f9fef0 |

- 起点：**绿色虚线圆环** #22c55e（半径 0.72 单元、线宽 0.2 单元、圆头虚线 dash≈0.39/0.32 单元），轻盈的"出发标记"感
- 终点：**玫红小旗帜** #f43f5e（白柔光底 r=1.1 单元 opacity 0.55 + 灰色旗杆 #8d8578 + 圆角三角旗面），一眼识别"到这儿就赢了"；缩略图中终点用金点 #f59e0b 以与小球区分
- 小球：**纯色圆，默认灰色 #64748b**（无描边、无高光，所有配色统一，与彩色墙面及起点/终点标记均不撞色）
- 墙渲染：每个墙单元一颗圆角糖块（内缩 2%，圆角 18%），单元间留极细缝形成"糖粒拼接"质感
- 摇杆固定淡紫配色（不跟随糖色谱）；「新迷宫」等主按钮颜色跟随当轮 wall 色
- 迷宫画布区固定浅色糖果底（不随暗色主题翻转，保证观感）；HUD / 按钮跟随应用主题（useTheme）

## 历史记录与成绩

- **最佳成绩**：`maze:best` → `{ [diff]: { timeMs, steps } }`，通关时若更快则更新，HUD 显示当前难度最佳
- **历史记录**：`maze:history`，通关自动 `unshift` 一条 `{ diff, seed, timeMs, steps, at, trail(编码) }`，上限 50 条（超出淘汰最旧）
- 历史面板：倒序列表（难度标签·用时·步数·种子·日期），点击 → 重建该迷宫并叠加幽灵轨迹 + 横幅（按钮：「📏 最短路径」切换显示青色虚线 #0d9488 的全局最短路（起点→终点，与灰色幽灵轨迹对比当年绕了多少）/「重新挑战」清空幽灵重玩 /「关闭」清除幽灵并退出查看）；每条带 × 删除
- **轨迹编码**（压缩存 AsyncStorage）：`16bit 步数 + 8bit 起始 i + 8bit 起始 j + 每步 2bit 方向（0上 2下 1右 3左）` → 字节流 → base64。约 0.3KB/千步

## RN 技术方案（方案 2：react-native-svg 混合架构）

选型背景（对比过"纯 RN View"与"WebView+Canvas"）：静态元素量大（地狱档 71×71 单元）、需要平滑轨迹线与未来特效扩展，SVG 优势明显；动态只涉及小球一个节点，用原生 View 层规避 SVG 高频更新。

- **静态层**：迷宫墙 / 起终点 / 轨迹 / 幽灵轨迹 → 一个 `Svg`（整图一次渲染，`React.memo` 锁死；轨迹按需增量或重绘）
- **动态层**：小球 = 绝对定位 `View`（圆形 + 描边），`setNativeProps` 直写 transform（60fps 不经过 React）；摇杆 = `PanResponder` 自研组件（底座 + 旋钮，pointer 捕获）
- **镜头**：外层裁剪 `View` + 内层容器 transform 平移；缩略图为独立小 `Svg`
- **依赖**：仅新增 `react-native-svg`（Software Mansion 维护、13.0+ 支持 Fabric 新架构）。**实现第一步先做冒烟验证**（安装 + 画 10 个 Rect + 新架构运行）；若与 RN 0.86 有兼容问题，回退纯 View 方案——算法层（形状/生成/物理/编码）两方案 100% 共用，回退成本低
- **模块接入**：`src/modules/maze/index.ts` 导出 `registerMazeModule()`；`App.tsx` 注册并挂两个路由：`MazeGame`、`MazeHistory`；`enabled: true`（双端通用）

## 验证记录（原型阶段）

浏览器原型 + Node 数值验证已完成：

- 生成器：5 种子 × 4 难度批量校验，起终点均在形状内且可达
- 物理：8 种子 × 4 难度 = 32 案例，各 1800 帧随机方向行走，**零穿墙**；BFS 路径自动导航均到达终点
- 轨迹编码：200 步随机轨迹编码→解码往返一致（72 字节）
- 渲染链路：无头浏览器截图验证——起终点/轨迹彩虹线/镜头跟随/缩略图/通关结算/最佳成绩均正常
- 开发中已修复的真实 bug：起终点行列转换错误、提示功能 BFS 坐标混用

**待真机验证项**：摇杆与镜头手势手感（模拟器/真机）、地狱档大迷宫在低端机的帧率、`react-native-svg` 与 RN 0.86 的兼容性冒烟。
