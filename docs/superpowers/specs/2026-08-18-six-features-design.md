# FlowKit 六大功能增强 — 设计文档

日期：2026-08-18
状态：已获用户批准（分 3 批实现）

## 背景

FlowKit 短信触发器已实现短信监听、规则匹配、动作执行（通知/震动/铃声/手表推送）与锁屏原生闭环（SmsNativeEngine）。本次新增 6 项功能，分 3 批落地。

## 功能清单与批次

| 批次 | 功能 | 核心改动 |
|------|------|----------|
| 批次 1 | #1 发送人黑白名单、#2 时间窗口 | 规则模型 + 匹配引擎（JS + 原生同步）|
| 批次 2 | #3 自诊断页、#5 触发统计报表 | 新页面 + 心跳/诊断数据 |
| 批次 3 | #4 模板库、#6 二维码导出分享 | 模板数据 + 二维码/扫码 |

## 批次 1：规则引擎增强

### #1 发送人过滤（黑白名单）

**需求**：规则级黑白名单，归一化精确匹配，通讯录多选 + 手动输入。

**数据模型**（`TriggerRule` 扩展）：
```ts
interface TriggerRule {
  // ...现有字段
  senderWhitelist?: string[];  // 仅限以下发送人（白名单）
  senderBlacklist?: string[];  // 排除以下发送人（黑名单）
}
```

**匹配逻辑**（JS `RuleEngine` 与原生 `SmsNativeEngine` 完全一致）：
1. **归一化**：号码去空格/横线/括号，去掉 `+86`/`+86-` 前缀（若剩余为 11 位数字）。
2. **黑名单**：归一化后 sender 命中黑名单任一 → 规则不匹配（直接短路）。
3. **白名单**：白名单非空时，sender 必须命中白名单任一 → 否则不匹配。
4. 通过过滤后，继续现有条件匹配（conditions AND 关系）。
5. 匹配顺序：**黑名单 → 白名单 → 时间窗口 → conditions**。

**UI（规则编辑页）**：
- 新增「发送人过滤」区段（位于条件区下方）：
  - 白名单/黑名单两个子区，各自：
    - chips 展示已添加号码（可删除）
    - 「从通讯录选择」按钮 → 通讯录多选弹窗
    - 「手动输入号码」按钮 → 输入弹窗
- 通讯录：申请 `READ_CONTACTS` 权限（首次使用时），原生 ContactsModule 查询联系人姓名+号码列表，RN 弹窗内搜索+多选，选中的号码加入名单。

**原生 ContactsModule**（新原生模块）：
- `getContacts(): Promise<{name, phones[]}[]>`：查询 ContactsContract（含手机号），返回姓名+号码列表。
- 权限未授予时返回错误，JS 侧引导授权。

### #2 时间窗口

**需求**：规则级单段时间窗口（支持跨天），默认 08:00-22:00，窗口外完全静默。

**数据模型**：
```ts
interface TriggerRule {
  // ...现有字段
  timeWindow?: {
    enabled: boolean;
    start: string;  // "HH:mm"
    end: string;    // "HH:mm"
  };
}
```
- 新规则默认 `{ enabled: true, start: '08:00', end: '22:00' }`（用户可关/改）。
- 兼容旧数据：无 `timeWindow` 字段的旧规则视为 `enabled: false`（不限制）——**或按需求默认 8-22？**（实现时决定：旧规则默认不限制，避免行为突变；新规则默认 8-22）。

**匹配逻辑**：
- `enabled === false` → 不限制。
- 非跨天（start <= end）：当前时间在 [start, end] 内才允许。
- 跨天（start > end，如 22:00-08:00）：当前时间 >= start 或 < end 才允许。
- 窗口外 → **完全静默**（不执行任何动作，包括原生闭环）。

**UI（规则编辑页）**：
- 「生效时间窗口」区段：开关 + 起止时间两个时间选择器（默认 08:00 → 22:00）。
- 起止时间交互：Android TimePicker 或自定义滚动选择（实现时定）。

### 原生引擎同步（关键）

`SmsNativeEngine`（Kotlin）同步升级：
- 规则快照 JSON 解析时读取 `senderWhitelist` / `senderBlacklist` / `timeWindow`。
- 匹配时按相同顺序（黑名单 → 白名单 → 时间窗口 → conditions）过滤。
- 保证**锁屏原生闭环触发也遵守黑白名单与时间窗口**。

## 批次 2：信息展示

### #3 自诊断页

**入口**：规则列表页「⋯」菜单 → 自诊断。

**内容**：
1. **保活服务卡片**：状态（运行中/已停止）+ 上次心跳（N 秒前）。
   - 心跳：KeepAliveService 每次轮询更新 `heartbeat_ts`（SharedPreferences），页面读取展示。
2. **权限状态网格**（4 项，✓/⚠ + 颜色）：
   - 短信接收（RECEIVE_SMS）——PackageManager.checkSelfPermission
   - 通知（POST_NOTIFICATIONS）——同上
   - 电池无限制——isIgnoringBatteryOptimizations（已有 API）
   - 自启动——小米 autostart 白名单（查询 powerkeeper/尝试写读；无法可靠查询时显示「请手动确认」并给引导文案）
3. **原生规则快照**：已同步条数（SmsNativeEngine 同步计数）。
4. **最近触发**：触发日志最新一条（规则名 + 时间）。
5. 异常项提供「去设置」引导（跳转对应系统设置页，用 Intent）。

**实现**：
- 新页面 `DiagnosticsScreen.tsx`。
- 心跳/快照计数：原生暴露 `getDiagnostics()`（返回心跳时间戳、快照条数、各权限状态）。
- 页面定时刷新（进入时 + 每 5 秒）。

### #5 触发统计报表

**入口**：规则列表页「⋯」菜单 → 触发统计。

**内容**：
1. **汇总卡**：总触发次数 / 近 30 天触发次数 / 动作成功率（成功动作数 ÷ 总动作数）。
2. **近 7 天分布**：按天柱状图（自绘 View，不引第三方图表库）。
3. **按规则排行**：各规则触发次数列表（降序）。

**数据来源**：现有触发日志（`RuleStorage` 的 ExecutionLog 列表，含 triggeredAt / actions 成功率）。统计在 JS 侧聚合。

## 批次 3：内容与分享

### #4 模板库

**入口**：规则列表页「＋」新建 → 弹层「选择模板 or 空白创建」。

**内置模板**（数组常量，`RuleTemplates.ts`）：
1. **🚗 违停提醒**：条件：正文包含「未按规定停放」；动作：通知 + 震动 + 铃声（默认 5 秒）。
2. **🔐 验证码提取**：条件：正文包含「验证码」；动作：通知（标题「验证码提醒」）。
3. **🏦 银行动账**：条件：正文包含「消费」或「入账」；动作：通知。
4. **📱 找手机**：条件：发送人 = [用户填自己的另一个号码]（模板创建后提示用户填入）；动作：铃声（默认 15 秒，闹钟流）+ 震动。

**交互**：点模板 → 预填到规则编辑页（规则名 = 模板名，条件/动作预填）→ 用户微调（尤其「找手机」需填号码）→ 保存。

**预留**：用户自定义保存为模板（批次 3 可先不做 UI，数据结构预留）。

### #6 二维码导出分享

**导出**（规则列表页 ⋯ → 导出规则）：
- 弹窗展示二维码（规则 JSON → Base64 → 二维码，本地生成）。
- 按钮：存为文件（JSON 文件，复用现有导出）/ 复制 JSON。
- 二维码库：`react-native-qrcode-svg`（轻量，无原生依赖）或原生生成——实现时验证包体积。

**导入**（⋯ → 导入规则）：
- 3 种方式：扫码导入（相机权限，仅此申请）/ 从文件导入（现有）/ 粘贴 JSON（现有）。
- 扫码：`react-native-vision-camera` 或 `react-native-camera`（需评估包体积与权限）——备选：原生二维码扫描模块（ML Kit / ZXing）。
- 扫码解析 → 预填到导入确认弹窗 → 导入。

**权限**：相机权限（CAMERA）仅在扫码导入时申请。

## 技术要点与约束

1. **规则模型兼容**：新增字段全部可选，旧规则数据（AsyncStorage 中）无需迁移即可加载。
2. **JS 与原生双引擎一致**：黑白名单/时间窗口逻辑在 `RuleEngine.ts`（JS）与 `SmsNativeEngine.kt`（Kotlin）各实现一份，逻辑保持一致（匹配顺序、归一化规则、跨天判断）。**这是最容易出 bug 的点，实现时两处逻辑逐行对照**。
3. **README / 测试**：规则引擎是纯函数，可单测（matchRule 的过滤逻辑）；原生引擎靠真机验证。
4. **包体积**：新增依赖尽量轻量（二维码生成用纯 JS 库；扫码评估体积后决定）。

## 验收标准

- 批次 1：规则可配黑白名单/时间窗口；锁屏原生触发遵守过滤（真机验证：黑名单号码锁屏不触发、窗口外不触发）。
- 批次 2：自诊断页正确显示心跳/权限/快照；统计报表数据与触发日志一致。
- 批次 3：模板一键建规则；二维码导出/扫码导入闭环可用。
